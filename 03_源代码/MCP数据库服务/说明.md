# MCP 数据库服务

## 文件 | 文件 | 说明 |
|---|---|
| `mysql_server_nodep.py` | **实际使用版本**，标准库手写 MCP 协议，仅依赖 pymysql |
| `mysql_server.py` | fastmcp 版本，保留作对照（安装依赖较重，未采用） |
| `test_mcp_nodep.py` / `test_mcp.py` | 协议连通性自测 |
| `requirements.txt` | 依赖清单 |

## 暴露的工具

| 工具名 | 参数 | 返回 |
|---|---|---|
| `execute_sqlstatement` | `sql`（string） | `{"ok": true, "count": n, "rows": [...]}` 或 `{"ok": false, "error": "..."}` |
| `list_tables` | 无 | 当前库的表名列表 |

## 为什么不用 fastmcp

`pip install fastmcp` 会连带拉几十个包，在受限网络下实测卡在 146 KB/s、缓存 30 秒不动。改用标准库 `http.server` 实现 `initialize` / `tools/list` / `tools/call` 三个方法即可，整个服务 300 行、只依赖 pymysql。

## 协议坑（重要）

对 `notifications/*` 这类通知请求，**必须返回 202 且响应体为空**。返回 204 会让 Dify 的 MCP 客户端报：

```
validation error for JSONRPCMessage
Invalid JSON: EOF while parsing a value at line 1 column 0
```

## 启动

```powershell
$env:MYSQL_HOST="192.168.1.10"; $env:MYSQL_PASSWORD="<MYSQL_PASSWORD>"; $env:MYSQL_DB="wechat"
python mysql_server_nodep.py
# → MCP 服务已启动: http://0.0.0.0:8095/mcp
# → 健康检查: http://127.0.0.1:8095/health
```

## 在 Dify 注册

工具 → MCP → 添加服务（HTTP）：URL `http://192.168.1.11:8095/mcp`，名称 `database_tool`，标识符 `database_server`。
